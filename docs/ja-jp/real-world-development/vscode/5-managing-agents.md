GitHub Copilot をエージェントモードで使うと、コードベースを調査し、変更を提案して、ファイルを編集し、コマンドを実行します。作業は開発者のマシン上でリアルタイムに進むため、VS Code の Copilot Chat には、各ツールの呼び出しやファイルの編集が逐次表示されます。差分をその場でレビューし、個々の変更を承認または取り消し、追加のプロンプトで会話を方向付けて、エディターから離れずに作業を改善したり拡張したりできます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイルの編集をレビューして承認します。
- セッションの途中でエージェントに指示を追加し、ハイコントラストに加えてライトモードの切り替えを実装します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントは、ハイコントラストモードを実装中です。作業中にデザインチームから追加の依頼がありました。デフォルトのテーマが暗すぎると感じる利用者向けに、ライトモードの切り替えも必要です。会話を最初からやり直す代わりに、既存のセッションに指示を追加し、作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが進める各手順が表示されます。調査したファイル、実行したコマンド、提案した編集を確認できます。ファイルの編集は差分とともにチャット内に表示され、**Keep** / **Undo** を選択できます。

1. 演習 4 で使用した Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナルコマンドなどが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャット内に表示されます。
    - **Keep** を選択して変更を適用します。
    - **Undo** を選択して変更を取り消し、エージェントにもう一度作業させます。
4. チャット上部の **Files changed** を開き、このセッションでエージェントが変更したすべてのファイルを確認することもできます。

> [!NOTE]
> ツールの呼び出し (ターミナルコマンドの実行など) に許可が必要な場合、エージェントは一時停止し、**Allow** を求めます。内容を確認し、実行を許可できるコマンドだけを承認してください。

5. エージェントがハイコントラストモードの実装を完了するまで待ちます。変更内容をまとめた最終メッセージが表示されます。

## ライトモードを追加するようエージェントに指示する

ハイコントラストモードを実装したら、同じ会話を続けてライトモードの切り替えを追加します。同じチャットセッションを続けることで、変更したコンポーネント、スタイルの方法、設定をローカルストレージに保存するパターンなど、前の作業のコンテキストがエージェントに引き継がれます。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    いいですね。次は、ハイコントラストの切り替えに加えてライトモードの切り替えも追加してください。ライトモードも同じ方法で設定をローカルストレージに保存し、同じユーザーインターフェイス (UI) 領域から操作できるようにしてください。利用者がハイコントラストとライトモードをそれぞれ独立して有効にできるようにします。
    ```

2. エージェントがすでに行った変更を調べて、ライトモードの追加を提案する様子を確認します。
3. ハイコントラストモードのときと同様に、新しい編集を 1 つずつ確認し、各差分で **Keep** または **Undo** を選択します。
4. エージェントが望ましくない方向に進んだ場合 (たとえば、気に入らない方法で切り替え UI をリファクタリングしようとした場合) は、チャット入力欄の横にある **Stop** ボタンで停止します。その後、明確な追加メッセージを送ります。

> [!TIP]
> 進行中のセッションに指示を追加すると、最初からやり直すよりも効率的です。追加プロンプトを使って、調整 ("Cascading Style Sheets (CSS) を簡潔にし、セレクターの重複ではなく CSS 変数を使う")、軌道修正 ("3 つ目の切り替えを追加せず、ライトモードを既存の設定パネルに統合する")、範囲の拡張 ("両方の切り替えにキーボードショートカットも追加する") を依頼できます。

## 作業内容をレビューする

変更をコミットする前に、エージェントが変更したファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが含まれます。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントから指示されたアクセシビリティのパターン (Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティックな HyperText Markup Language (HTML)、ローカルストレージへの保存) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次の[レッスン][next-lesson]で公開します。

## まとめと次のステップ

このレッスンでは、Copilot Chat のエージェントモードを使い、進行中のセッションを監視して方向付けました。各ファイルの編集を確認し、変更を承認または取り消し、コンテキストを引き継いだまま追加プロンプトで作業を拡張しました。

次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を承認または取り消しました。
- 追加プロンプトで進行中のセッションに指示を加えました。

次の[レッスン][next-lesson]では、アクセシビリティの作業をプルリクエストとして公開し、このラボでローカルのカスタムエージェントが作成した変更をレビューします。
