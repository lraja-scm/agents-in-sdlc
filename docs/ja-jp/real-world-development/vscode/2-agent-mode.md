アプリケーションを少し変更するだけでも、複数のファイルの更新やテストの実行が必要になることがあります。開発者は通常、必要なファイルを探し、変更を加え、テストを実行し、問題をデバッグし、変更し忘れたファイルを見つけてさらに更新します。このような作業は続くことがあります。

ここで役立つのが Copilot エージェントモードです。

Copilot エージェントモードは、統合開発環境 (IDE) 内でより自律的に動作します。まず既存のプロジェクト構成を調べ、必要なファイルを更新し、テストなどのタスクを実行して、見つかった問題を自動的に修正します。ここでは、エージェントモードを使ってサイトに機能を追加する方法を確認します。

> [!NOTE]
> 名前は似ていますが、エージェントモードとクラウドエージェントは異なる用途向けに作られています。エージェントモードは IDE 内でタスクを実行し、すばやいフィードバックと対話を可能にします。クラウドエージェントはチームメンバーのように非同期で作業し、Issue とプルリクエストを通じてやり取りします。

この演習では、次の方法を確認します。

- Copilot エージェントモードでプロジェクトを調査し、関連ファイルを特定して、連携した変更を加えます。
- GitHub Copilot エージェントモードでユーザーインターフェイス (UI) とデータ層にまたがる新機能を実装します。
- コードベースにマージする前に、Copilot エージェントモードが生成した変更とテストをレビューします。

## シナリオ

ゲームの数が増えてきたため、利用者がカテゴリとパブリッシャーで絞り込めるようにします。前の演習でパブリッシャー用ヘルパーを追加しました。ここでは Copilot エージェントモードを使い、残りのデータ層、UI、テストの作業を完了します。

## Tailspin Toys の Web サイトを実行する

変更を加える前に、Tailspin Toys の Web サイトを確認し、現在の機能を把握します。

この Web サイトは、開発者をテーマにしたボードゲームのクラウドファンディングプラットフォームです。ゲームの一覧と詳細を表示します。Astro アプリは 1 つで、ビルド時にページを静的な HyperText Markup Language (HTML) としてレンダリングします。ページでは、オブジェクトリレーショナルマッパー (ORM) である Drizzle を使って、フロントマターからローカルの SQLite データベースに直接クエリを実行します。独立したバックエンドのアプリケーションプログラミングインターフェイス (API) やクライアントサイドのユーザーインターフェイス (UI) フレームワークはありません。再利用可能なデータアクセスヘルパーは `src/lib/` に配置し、インタラクティブ機能にはドキュメントオブジェクトモデル (DOM) API を使う小規模な Astro `<script>` を追加します。

### Web サイトを起動する

`npm run dev` タスクを使うと、単一の Astro 開発サーバーを起動できます。次の手順で GitHub Codespace 内から実行します。

1. codespace に戻ります。前の演習を終えていれば、`main` ブランチにいます。
2. <kbd>Control</kbd>+<kbd>`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>`</kbd> (Windows/Linux) を押して、codespace 内に新しいターミナルを開きます。
3. 次のコマンドを実行して、フィルター作業用のブランチを作成し、切り替えます。

   ```bash
   git checkout main
   git pull
   git checkout -b filtering-vscode
   ```

4. 次のコマンドを実行して、Web サイトを起動します。

   ```bash
   npm run dev
   ```

   Astro 開発サーバーの準備ができると、次のような Uniform Resource Locator (URL) を含むバナーが表示されます。

   ```bash
   🚀 Tailspin Toys is ready!
      Astro server: http://localhost:4321
      Press Ctrl-C to stop.
   ```

> [!NOTE]
> `http://localhost:4321` を開くよう促すダイアログが表示された場合は、**x** を選択して閉じます。

5. ターミナルで Astro サーバーのアドレス `http://localhost:4321` を選択します。Mac では <kbd>Command</kbd> キー、Windows/Linux では <kbd>Ctrl</kbd> キーを押しながら選択します。

> [!NOTE]
> codespace を使っている場合、codespace のターミナルから localhost の URL を選択すると、自動的に `https://<your-codespace-name>-4321.app.github.dev/` にリダイレクトされます。これは、Web サーバーをホストする codespace へのプライベートトンネルです。

### Web サイトを確認する

Web サイトを起動したら、現在の機能を確認します。主な機能は次のとおりです。

- **ホームページ**: ボードゲームのタイトル、画像、説明の一覧を表示します。
- **ゲーム詳細ページ**: ゲームを選択すると、タイトル、説明、パブリッシャー、カテゴリなどの詳細を表示します。

## Copilot でバックログを確認する

> [!TIP]
> **Copilot Chat を開く**
>
> この演習では Copilot Chat の新しい会話を使います。モードとモデルの選択は演習によって異なるため、必要な箇所で説明します。

Web サイトの初期実装は動作しますが、新しい機能を追加して改善します。まず、バックログを確認します。テンプレートからプロジェクトをセットアップすると、Issue のバックログが自動的に作成されています。GitHub Copilot に項目を表示するよう依頼します。

1. codespace に戻り、Copilot Chat パネルを開いて **New Chat** を選択し、新しい会話を開始します。次に、Chat ビューのエージェントのドロップダウンから **Agent** を選択します。**Agent** は自律的に変更を計画して複数のファイルに実装し、ターミナルコマンドを実行してツールを呼び出します。

   ![Chat ビューのエージェント選択メニュー](../../../_images/shared-chat-mode-selector.png)

2. 利用可能なモデルの一覧から **Claude Sonnet 4.5** を選択します。

> [!CAUTION]
> このワークショップの作成者は、特定のモデルを推奨しているわけではありません。ワークショップ作成時に Claude Sonnet 4.5 を使用したため、体験を安定させる目的で手順に記載しています。ただし、大規模言語モデル (LLM) は確率的に動作するため、手順に示したものと異なる提案が出ることがあります。これは正常な動作です。

> [!NOTE]
> LLM の確率的な性質により、Copilot が別の Model Context Protocol (MCP) コマンドを使う場合がありますが、タスク自体は完了できます。

3. 次のプロンプトを Copilot に送信し、Issue のバックログを確認します。

   ```plaintext
   GitHub リポジトリのバックログにある項目を表示してください。利用者にとって最も役立つ項目を基準に、優先順位付けを手伝ってください。
   ```

4. **Continue** を選択し、すべての Issue を一覧表示するコマンドを実行します。
5. 生成された Issue の一覧を確認します。

Copilot が、利用者にとって最も役立つと判断した項目から優先順位を付けたことを確認します。

## 指示ファイルを確認する

Copilot にコードを生成させる前に、作業のコンテキストとして使う指示ファイルを確認します。ここでは、Web サイトへの機能追加方法を説明する[ユーザーインターフェイス (UI)](https://github.com/github-samples/tailspin-toys/blob/main/.github/instructions/ui.instructions.md) ファイルを使います。

1. codespace で `.github/instructions/ui.instructions.md` に移動します。
2. 機能追加に関する全体的なガイダンスを確認します。次の内容が含まれます。
   - アーキテクチャの概要。
   - コンポーネント設計、テスト容易性、アクセシビリティの原則。
   - Astro、Tailwind CSS、Drizzle など、各種ファイル向けの指示ファイルへのリンク。

> [!TIP]
> 指示ファイルから、ほかの指示ファイルやプロジェクト内のファイルを参照できます。パスは指示ファイルからの相対パスです。これにより、指示を再利用したり、複雑な内容を管理しやすい小さなファイルに分けたり、コード生成時に参照する例やテンプレートを示したりできます。

## フィルター機能を実装する

フィルター機能を完成させるには、アプリケーションに少なくとも 3 つの変更が必要です。

- データ層 (`src/lib/`) の残りのフィルターロジックを追加または調整します。
- フィルターの動作に関するテストを追加または更新します。
- ゲーム一覧ページを更新して、フィルター UI を追加します。

また、コードベースにマージする前にテストを実行し、成功させる必要があります。Copilot エージェントモードにこれらの作業を任せましょう。

1. Copilot との現在の会話を続けるか、**New Chat** を選択して新しい会話を開始します。
2. **Add Context**、**Instructions**、**ui** の順に選択し、指示ファイルを指定します。

   ![UI 指示ファイルを選択する例](../../../_images/ex3-select-instructions-file.png)

3. Chat ビューのエージェントのドロップダウンで **Agent** が選択されていることを確認します。

   ![Chat ビューのエージェント選択メニュー](../../../_images/shared-chat-mode-selector.png)

4. モデルとして **Claude Sonnet 4.5** が選択されていることを確認します。
5. バックログにある関連 Issue の要件に沿って機能を実装するよう、次のプロンプトで Copilot に依頼します。

   ```plaintext
   バックログ内の関連する GitHub Issue の要件に基づき、サイトにパブリッシャーとカテゴリによる絞り込み機能を追加してください。前の演習でパブリッシャー用ヘルパーはすでに作成されているので、必要に応じて既存の作業を維持・改善しながら、残りのデータ層、UI、テストを完了してください。完了前にすべてのテストが成功することを確認してください。サーバーはすでに起動しているため、起動する必要はありません。
   ```

6. Copilot がプロジェクトを調査し、必要な機能に関連するファイルを特定する様子を確認します。データ層のヘルパー、UI、テストを見つけた後、ファイルの変更とテストの実行を始めます。

   ![Copilot がプロジェクトのファイルを調査している画面](../../../_images/ex3-agent-mode-explores.png)

> [!NOTE]
> Copilot はプロジェクトの調査、ファイルの変更、テストの実行など、複数のタスクを実施します。タスクやコードベースの複雑さによっては数分かかる場合があります。作業中、コードエディターに **Keep** と **Undo** が表示されることがあります。Copilot が完了すると、すべての変更に対して **Keep** または **Undo** を選択できるようになります。作業中に選択する必要はありません。

7. Copilot に求められたら、**Continue** を選択してテストを実行します。

   ![Copilot Chat ペインにテスト実行の確認を求めるダイアログが表示された画面](../../../_images/ex3-agent-mode-run-tests.png)

8. 作業中に一時停止したり、テストが失敗したりすることがあります。問題ありません。Copilot はタスクを完了し、エラーが見つからなくなるまでコード生成とテストを繰り返します。

   ![Copilot エージェントモードのセッションが完了した画面](../../../_images/ex3-agent-mode-proposed-changes.png)

9. 生成されたコードに問題がないか確認します。

> [!CAUTION]
> Copilot などの人工知能 (AI) ツールが生成したコードは、必ずレビューしてください。

10. Web サイトを起動したブラウザーに戻り、新しい機能を確認します。
11. 動作を確認し、コードをレビューしたら、Copilot Chat ウィンドウで **Keep** を選択します。

## まとめと次のステップ

この演習では、GitHub Copilot エージェントモードを使って Tailspin Toys の Web サイトに機能を追加する方法を確認しました。次のことを行いました。

- GitHub Copilot エージェントモードで UI とデータ層にまたがる新機能を実装しました。
- Copilot エージェントモードでプロジェクトを調査し、関連ファイルを特定して、連携した変更を加えました。
- コードベースにマージする前に、Copilot エージェントモードが生成した変更とテストをレビューしました。

次は、[Playwright MCP サーバーで機能をテストし][next-lesson]、プルリクエストを作成します。

### 追加演習 – ページネーションを実装する

ゲーム一覧が増えるにつれて、ページネーションが必要になります。この演習で学んだことを使い、Copilot にページネーションを実装するよう依頼します。コードを作成するときは、次の点を検討してください。

- 既存の指示ファイルを使うなど、既存のベストプラクティスに従います。
- ページサイズを利用者が選べるようにするか、固定値にするかなど、ページネーションの実装方法を検討します。
- 希望どおりに実装できるよう、Copilot に必要な情報をプロンプトに含めます。
- GitHub Copilot とやり取りし、コンテキストを追加して変更を依頼する必要がある場合があります。これは Copilot を使う通常の作業方法です。
